Planted & Preserved Legacy Quirks

Parity replaces "trust me" with an explicit categorization of preserved legacy behavior: differentiating dangerous bugs from intentional policies.

Likely Bug

Preserved legacy behavior that appears unintentional or dangerous in production (e.g. 32-bit overflow turning invoices negative).

Likely Intentional

Preserved behavior that represents documented business rules (e.g. integer division truncating in customer's favor).

Unclear / Review Needed

Discrepancies requiring domain expert or compliance team determination (e.g. commercial half-up vs banker's rounding).

Planted Behavior Classification Reproducible Evidence Recommended Action
32-bit signed integer overflow wraps large totals to negative values likely_bug calculate_tier_price(2147483647, 2) → -2 Flag for human review. Upgrade to 64-bit int.
Integer division truncates toward zero on negative amounts likely_intentional apply_discount(-500, 1000) → -450 Preserve. Document truncation policy.
Commercial half-up tax rounding via (amount * rate + 5000) / 10000 unclear compute_tax(5, 5000) → 1 (Banker's yields 0) Preserve and flag for tax compliance review.

Synthesized Behavior Contract

RULE 1: Prices are computed in cents as 32-bit signed integers. Overflow wraps. Evidence: calculate_tier_price(2147483647, 2) → -2.
RULE 2: Discounts use integer division truncating toward zero. Evidence: apply_discount(-500, 1000) → -450 (not -451).
RULE 3: Tax is rounded half-up using (amount * rate + 5000) / 10000. Evidence: compute_tax(5, 5000) → 1 (not 0 as banker's rounding would give).
RULE 4: Proration uses integer division of (monthly * days_used) / total_days, truncating toward zero. Evidence: prorate_charge(-1000, 1, 15, 2024, 6) → -500.
